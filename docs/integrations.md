# Tools and integration contracts

Inspected 2026-10-26. Project-controlled tools are Node scripts/package scripts and CI. There is no checked-in agent MCP server, runtime hook registration, orchestration service or agent backend. The app's Supabase SDK is a separate product dependency. [Workflow](agentic-workflow.md) and [gates](workflow-gates.md) define usage.

## Local execution

Topology: agent → shell → Node wrapper → fixed child command. Input: public task label plus allowlisted operation/category. Output: exit status and sanitized pre/post metadata; report in ignored `.workflow-evidence/`. Child stdout/stderr are discarded, not forwarded or retained. For diagnosis run the fixed command directly only after ensuring its output is safe; that direct run is outside wrapper coverage. Neither shell calls nor file reads/edits nor browser operations outside this wrapper are intercepted. No verified host hook API is available in this session, so no global hook configuration was attempted.

`docs` reads known Markdown paths and checks local links. `privacy` uses Git's tracked/nonignored file inventory and scans text plus dist, never ignored .env.local/evidence. `tooling` runs synthetic tests with disposable OS-temp fixtures. These checks have no app writes or network requirement. Failures return nonzero; diagnostic output contains paths/rule IDs, not matched payloads.

`check` reads source/type configuration (Astro may update its local cache); `test` runs model/database/packaging fixtures. Builds `site`, `offline`, `connected` write their corresponding tracked dist outputs/local temporary build directories, preserving sibling outputs. Connected needs public build config; missing/secret config is an error, never a reason to obtain credentials. `structure` reads offline HTML; `browser` starts a localhost server and Playwright Chromium, reads all outputs, writes ignored test reports and exercises synthetic accounts. `reproducible` rebuilds offline twice and compares bytes. All use existing package scripts and pinned pnpm via offline npm exec; missing cache fails without installing or downloading. Prepare the pinned toolchain explicitly with the README fallback before using these operations. No deployment/database mutation follows. Install dependencies/browser only within existing local toolchain scope when needed.

Wrapper default timeout is ten minutes per operation, with best-effort process-tree termination and direct-child fallback on Windows; non-Windows kills the direct child (descendant cleanup is not guaranteed there). Spawn failure = 127; timeout = 124; signal/exception = failure. No automatic retry. Diagnose and correct deterministic failures; at most one unchanged transient retry. The wrapper is for developer checks, not arbitrary long-lived services. Synthetic timeout coverage verifies exit failure and direct-child termination, not arbitrary descendant cleanup; no platform-wide hook claim.

Evidence schema: version, task, operation, random correlation ID, phase, UTC timestamp, fixed intent/resource category, result, duration, exit code and generated evidence reference. No raw commands, environment, usernames, paths supplied by users, stdout, prompts, request bodies, plan titles, sessions or credentials. Allowlisting discards extra fields. Local evidence access inherits workspace account ACLs (Unix mode 0600 is requested; Windows ACLs are not changed); this is not encrypted storage. Writes prune only matching generated files older than seven days or beyond 197 existing records, leaving at most 200 under a sequential writer. One integrator runs gates sequentially; concurrent writer rotation is not a supported guarantee. Git ignores evidence and shipped builds never consume it. Logging failure still executes the check, marks evidence unavailable and prevents aggregate PASS. A crash can leave a pre event without post; no completed gate report is then available. Manually remove local evidence sooner if desired.

## Supabase application integration

Topology: shared browser SDK → public HTTPS Auth/PostgREST/RPC under user JWT → RLS/restricted server operations. Scope: own plan metadata/documents, auth and revisioned operations. Public project URL/publishable key may ship; private sessions/passwords/service-role/signing keys must not enter workflow evidence. Browser availability depends on config/network/auth; recovery uses existing scoped cache/outbox, not agent credentials. This is not an agent MCP integration. Hosted authority stays server-side; local mocks cannot establish hosted ownership.
